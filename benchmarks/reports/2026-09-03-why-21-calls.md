# Why Norn makes 21 LLM calls where Terminus-2 makes 9 (2026-09-03)

Follow-up to the Rosetta re-run: Norn was 2× slower than Terminus-2 on 19/20
tasks with negligible tool time, i.e. the gap is LLM round-trips. This digs
into the per-call structure of both agents on the same 20 tasks.

## Method and a correction

Norn's per-call JSONL logs were not shipped out of the container (fixed in
the adapter: `logging.file_dir=/logs/agent/norn-logs`, synced by harbor).
So this analysis reconstructs Norn's sequence from `norn.txt`: one
`PydanticSerializationUnexpectedValue` warning per LLM call, one indented
`tool: ...` line per tool call. Terminus-2 has a proper ATIF trajectory.

A first pass reported "51% idle turns". **That was a regex artefact** (it
missed `FAIL`-ending bash lines and `file_write` lines without a duration).
Correct count: **4 pure idle turns out of 416 (1%)**. Norn does not waste
turns thinking. The idle-turn hypothesis from the Scaffold Effect paper does
**not** apply here.

## The actual mechanism: batching

| | Terminus-2 | Norn |
|---|---|---|
| LLM calls, 20 tasks | **167** | **416** |
| tool calls, 20 tasks | 566 | 474 |
| **tool calls per LLM call** | **3.39** | **1.14** |
| pure idle turns | — | 4 (1%) |

Both agents do roughly the **same amount of tool work** (~500 commands).
Terminus-2 emits 3–6 commands per turn; Norn emits one. Every Norn command
pays a full LLM round-trip with the full context re-sent.

Concrete, `fix-git` (both pass): Terminus-2 step 2 = `pwd; git status -sb;
git branch -avv; git log ...; git reflog ...; git stash list` in ONE call.
Norn spends calls #1–#5 issuing those same reads one at a time.
Result: 9 calls vs 14 on an easy task; 21 vs 9 median overall.

## Root cause is ours

`src/norn/core/prompts.py:22`:

> "One tool call per step when sequence matters. Parallel calls when independent."

The model follows the instruction. In a terminal task nearly everything
"matters in sequence" from the model's point of view, so it serialises. The
"parallel when independent" clause is not enough to counterweight it.

Cost of this line, measured: ~2.5× LLM calls, ~2× wall-clock, ~2× premium
interactions, for **no** pass-rate benefit (Norn 40% vs T2 60% on this set).

## What to try (cheapest first)

1. **Prompt**: replace the line with explicit batching guidance — "issue all
   independent read-only commands of a phase in one turn; chain dependent
   shell steps with `&&` in a single bash call; one call per turn only when
   a decision depends on the previous output". Zero code. Measurable on the
   same 20 tasks for ~300 interactions.
2. **Tool shape**: Terminus-2's tool takes a *list* of commands with
   per-command timeouts. A `bash` input accepting `commands: list[str]`
   (run sequentially, stop on first failure, return per-command output)
   would make batching structural rather than prompt-dependent.
3. Keep `auto_verify` — it accounts for only 27 of 416 calls (6%) and is
   not the problem.

## Caveats

Norn call counts inferred from a warning line, not events (fixed for next
run). Batching more commands per turn trades round-trips for longer tool
outputs per turn; the `max_turn_output_chars` budget (30k) and AXI
truncation should absorb that, but watch context growth on the re-run.
